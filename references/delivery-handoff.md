# Delivery handoff

A delivery is useful when another person can understand what changed, run it, inspect the same artifact, and see what remains uncertain.

## Use a bounded claim

State the actual scope. Do not hide unresolved mobile, scroll, performance, dependency, or runtime issues inside a cheerful completion message.

## Include

- goal and accepted baseline;
- changed areas and how to run;
- evidence location and verdict;
- known limits, not merely successes;
- one recommended next action.

## Exclude

Credentials, environment files, private assets, local caches, generated dependency trees, unrelated history, and any evidence that identifies a client or private project. Use `templates/handoff.md` when a consistent form helps.
